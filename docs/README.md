# Docs

Map of what's here. Filing rules (which bucket a new doc/lesson goes in) live in `lessons/README.md`
for lessons; the rules below cover the rest.

## What's here

- **`archive/`** — shipped, superseded, or abandoned plans and analyses. Historical record: don't
  delete or edit into the present tense, only add a corrected `Status:` line naming what actually
  happened.
- **`planning/`** — still-active, not-yet-decided plans. Distinct from `archive/`: nothing here
  should be treated as settled just because it's written down.
- **`lessons/`** — non-obvious gotchas, one location repo-wide (all subprojects). See its own
  `README.md` for filing rules.
- **`log/`** — append-only, dated record of closed/paused milestones. See `log/INDEX.md`.
- **Root** — evergreen reference docs that fit no bucket above. Kept intentionally small; if root
  accumulates files, split into `planning/` + `archive/`.

## Citing other docs: the `Id:`/`[[id]]` convention

A bare relative-path citation breaks silently on move or rename. New docs use a stable id instead:

- **`Id:`** — a line under the H1, e.g. `Id: implementation-plan`. Kebab-case, assigned once,
  **never renamed** even if the title changes later.
- **Cite it as `[[implementation-plan]]`** in prose. Resolves against the repo-wide id index, so the
  doc can move without breaking citers.
- **`[[id#anchor]]`** for passage-level precision — the anchor is the target heading's own slug.
- **Old-style path citations still resolve** — `check-links.py` runs both mechanisms side by side.
  New docs use `Id:`/`[[id]]`; existing ones adopt it when next touched.
- `[[id]]` renders as literal bracketed text on GitHub. [`_ids.md`](_ids.md) (id, current path,
  title) is the human lookup — generated by `check-links.py`, never hand-edited.

## After every move

Run `python3 docs/check-links.py` and `bash docs/check-lessons.sh`, and `grep -rn '<old-filename>'`
over the whole repo (not just `docs/`) — the checker also scans `.claude/skills/`, root files, and
the root slice docs, but a citer anywhere else can go dead silently. Convert what the grep finds to
`[[id]]`.
